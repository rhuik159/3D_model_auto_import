# 후속 과제 — Xpedition 자동화 및 매핑 포맷

## 1. 3D 매핑 파일 포맷 — 완료 (2026-09-16)

`Mapping.xdm` / `Alignment.dat` 생성이 구현되었다.
제공된 샘플과 **바이트 단위로 동일**함을 검증했다 (MD5 일치).

- 구현: `src/Step3.MappingFile.ps1`
- 형식 상세와 제외 규칙은 `docs/README.md` 의 "Mapping.xdm / Alignment.dat" 참조
- FPT / XDP 는 둘 다 확장자를 제외한 파일명을 사용한다

### Import 동작 — 확인 완료 (사용자 확인)
Xpedition 의 매핑 Import 는 **누적(additive)** 방식이다.

- 매핑 파일에 없는 부품이라도 **이전에 등록된 것은 해제되지 않는다.**
- 이전에 처리한 부품을 다시 넣으면 **덮어쓰면서 업데이트**된다.

따라서 그날 업데이트된 부품만 담는 현재 방식이 맞으며,
누적 전체 목록을 만들 필요가 없다. 같은 부품이 여러 날짜 폴더에
반복 등장해도 마지막 Import 가 반영되므로 문제되지 않는다.

### 남은 확인 사항
- 한글 파일명 모델은 ASCII 제약으로 매핑에서 제외된다. 해당 모델이 실제로
  존재한다면 파일명 영문화 규칙을 정하는 편이 좋다.

## 2. Xpedition Import 자동화 가능 여부 조사

현재 5~6단계(3D Model Import, 매핑 Import)는 **수동**이다.

> **주의**: 이 환경에서는 웹 검색이 조직 정책으로 차단되어 있어
> Xpedition 자동화 인터페이스의 존재 여부를 확인하지 못했다.
> **API 가 있다고 가정하지 않았다.** 아래는 확인해야 할 경로 목록이다.

### 확인 경로
1. **Xpedition 설치 폴더** — automation / scripting 관련 문서·샘플 디렉토리
   (일반적으로 `<설치경로>\doc`, `\examples`, `\scripts`)
2. **Siemens Support Center** — Xpedition Automation / Library Manager
   배치 인터페이스 문서
3. **사내 CAD 관리팀** — 이미 사용 중인 배치 스크립트가 있을 가능성
4. Xpedition 메뉴에서 해당 Import 동작의 **로그/저널 파일**을 확인하면
   내부적으로 호출되는 명령이 드러나는 경우가 있음

### 조사 시 확인할 것
- COM 자동화 인터페이스 제공 여부
- 커맨드라인/배치 실행 지원 여부
- 스크립팅 언어 (TCL 등) 지원 여부
- 무인 실행 시 라이선스 점유 방식

자동화가 가능하다고 확인되면 `src/Step5.Import.ps1` 을 추가하고
오케스트레이터에 단계를 끼워 넣는 구조로 확장한다.

## 3. 기타

- **날짜 폴더 보관 기간** — 실제 배치 크기를 파악한 뒤
  `config.json` 의 `retention.dateFolderDays` 값을 정한다.
  현재는 `0`(자동 삭제 안 함)이다. 담당자가 아직 Import 중일 수 있는
  작업 배치이므로 섣불리 지우지 않는 편이 안전하다.
- **상태 조회 스크립트** — 마지막 실행 시각·종료코드·변경 건수를 보여주는
  `Get-SyncStatus.ps1` 을 추가하면 운영이 편해진다.
- **긴 경로 정책** — 이 PC 에서 `LongPathsEnabled = 0` 으로 확인되었다.
  스크립트는 `\\?\` 접두사로 대응하고 있으나, 운영 배포 시 그룹 정책으로
  `LongPathsEnabled = 1` 을 적용하면 더 안전하다.
